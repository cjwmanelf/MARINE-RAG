# 🚢 MARINE RAG — 선박기기 매뉴얼 RAG 안내 챗봇

> 선박기기 매뉴얼 PDF를 **완전 로컬**로 색인·검색하고, **근거 기반(RAG)** 으로 답해 주는 도구.
> 스캔본/텍스트본 PDF를 모두 지원하며, **한글로 물어도 영문 매뉴얼**이 매칭됩니다. (예: `산소 분석기` → `oxygen analyzer`)

---

## 📖 서비스 소개

선박기기 매뉴얼 RAG 안내 챗봇은 선박기관사·정비 엔지니어가 종이·PDF 매뉴얼을 목차부터 손으로 뒤지는 대신, **자연어로 물어 근거 기반 답**을 받게 하는 로컬 우선 도구다. 스캔본·텍스트본 PDF를 색인해 **도면·표(이미지)와 본문(다국어 텍스트)을 함께 검색**하고, 로컬 LLM이 **검색된 근거만으로** 답하며 `[출처 파일 · p쪽]`으로 원문을 즉시 검증하게 한다. 한글로 물어도 영문 매뉴얼이 매칭되고(예: `산소 분석기` → `oxygen analyzer`), 근거가 없으면 지어내지 않고 "확인되지 않습니다"로 답한다. 외부 통신이 제한되는 선박 환경을 전제로 **기본은 완전 로컬**로 동작한다(외부 API는 수동 전환 시에만).

## 🧩 두 가지 실행 방식 — 로컬 파이썬 앱 vs 웹 데모

이 저장소에는 **두 개의 실행 경로**가 있습니다(같은 RAG 개념, 실행만 다름).

| | 🖥️ 파이썬 앱 (`run.bat` / `app.py`) | 🌐 웹 데모 (`web/`, GitHub Pages) |
|---|---|---|
| 용도 | **실제 로컬 풀버전** | **공개 쇼케이스** |
| 실행 | `run.bat`(=`python app.py`) → `localhost:7860` | `npm run dev` 또는 배포 URL |
| 데이터 | 실제 매뉴얼(로컬 전용) | 공개 합성 샘플 |
| 기능 | 색인·검색·챗봇 전부 | 챗봇(검색+생성) |
| 임베딩 | 색인 시 미리 계산(bge-m3, 서버) | 브라우저 즉석(e5-small) |
| 생성 | 서버가 로컬 Ollama 호출 | 방문자 브라우저가 각자 로컬 Ollama 호출 |

**웹 데모를 따로 만든 이유**
- **공개 배포 주소가 필요** — 파이썬 앱은 로컬/사내망이라 공개 URL이 없음. GitHub Pages는 무료 공개 HTTPS 주소를 제공.
- **서버 비용 0** — 정적 페이지 + 방문자 각자의 브라우저가 임베딩하고 자기 Ollama를 호출 → 서버에 GPU/LLM 불필요.
- **데이터가 클라우드로 안 감** — 생성이 각자 로컬 Ollama에서 일어나 "로컬" 철학 유지.
- **Gradio 공개 배포의 난점 회피** — 파이썬 챗봇은 서버에 Ollama가 떠 있어야 해 공개 호스팅이 무겁고 비쌈.

> 요약: **실제 업무용 = 파이썬 앱(`run.bat`)**, **공개 시연용 = 웹 데모**. 웹 데모는 공개 배포라 샘플 데이터를 쓰고, HTTPS→로컬 Ollama 호출엔 프록시가 필요합니다(아래 참고).

## 🌐 웹 데모 (정적 JS · GitHub Pages)

로컬 Gradio 앱 외에, **각 사용자의 브라우저가 자기 PC의 Ollama를 직접 호출**하는 정적 웹 데모도 제공합니다(`web/`).

- **배포 주소(라이브)**: ✅ https://cjwmanelf.github.io/MARINE-RAG/
- **구조**: 브라우저에서 임베딩(transformers.js `multilingual-e5-small`)+코사인 검색 → 사용자 로컬 Ollama(`qwen3.5:2b`, `think:false`) 직호출 → 폐쇄형 답변·`[출처]` 인용
- **근거 데이터**: 공개용 **합성 샘플 매뉴얼**(`web/public/chunks.json`) — 실제 보안 매뉴얼 아님
  - 색인앱(`app.py`)으로 만든 실제 세트를 웹 데모에 실으려면: `python tools/chunks_to_web.py <세트>` → `web/public/chunks.json` 갱신 → 재빌드/배포. (`indexes/<세트>/chunks.jsonl` → 웹 형식 변환. ⚠️ **공개 배포는 공개 가능한 자료만**)

**사용 조건 (숨기지 않습니다)**
1. 본인 PC에서 **Ollama 실행 + `ollama pull qwen3.5:2b`**
2. **첫 방문**에 임베딩 모델(수백 MB)이 브라우저로 다운로드됨 — 잠시 대기 (임베딩·검색은 설정 없이 동작)
3. 답변 **생성**은 아래 (A) 또는 (B):

**(A) 배포(HTTPS) 사이트에서 생성 — PNA 우회 프록시 실행**
HTTPS 페이지가 HTTP 로컬 Ollama를 직접 부르면 브라우저 **PNA(Private Network Access)** 정책에 막힙니다(`net::ERR_BLOCKED_BY_CLIENT`; Ollama가 PNA 허용 헤더를 안 줘 **CORS로도 해결 안 됨**). 그래서 **PNA/CORS 헤더를 붙여 Ollama로 전달하는 초소형 프록시**를 함께 실행합니다(의존성 0):
```bash
# Ollama가 실행 중인 상태에서
node web/ollama-proxy.mjs      # http://localhost:11435 → Ollama(11434)로 전달, PNA 헤더 추가
```
→ 배포 사이트가 **자동으로 이 프록시를 통해** 생성합니다(HTTPS면 프록시 우선). `OLLAMA_ORIGINS` 불필요(프록시가 서버-사이드로 Ollama 호출).

**(B) 로컬(HTTP)로 실행 — 프록시 불필요**
```bash
cd web && npm install && npm run build && npm run preview   # http://localhost:4173
# 개발용: npm run dev                                        # http://localhost:5173
```
→ HTTP↔HTTP라 PNA 장벽이 없어 직접 동작합니다(검증됨).

> 연결 실패 시 답변 영역에 원인·재시도 방법이 표시됩니다(페이지 오류와 구분).
> 배포 확인 순서: ① 주소 열기 → ② Ollama+모델 준비 → ③ 첫 방문 임베딩 다운로드 대기 → ④ (배포 사이트면) `node web/ollama-proxy.mjs` 실행 → ⑤ 소개 질문·자료 밖 질문 입력해 출처/거부 확인.

## ✨ 기능

- **하이브리드 검색** — 도면·표(이미지) + 본문(다국어 텍스트)을 동시에 검색
- **근거 기반 답변 (폐쇄형 RAG)** — 로컬 LLM이 **검색된 근거만으로** 답하고, 근거가 없으면 지어내지 않고 "확인되지 않습니다"
- **출처·그림** — 답변에 `[출처 파일 · p쪽]` 인라인 인용, 관련 도면·표는 클릭해 확대
- **구조화 청크 산출물** — 색인 시 `chunks.jsonl` + `verify_report.md` 자동 생성
- **완전 로컬** — 외부 통신 없이 동작(모델 가중치만 최초 1회 다운로드). 유료 API는 선택·수동

## 🖥️ 화면 (탭)

| 탭 | 설명 |
|---|---|
| 📁 색인 생성 | PDF 드래그앤드롭 → 이미지+텍스트 색인, 세트별 관리(추가/덮어쓰기) |
| 🔍 하이브리드 검색 | 질의어로 도면·표 + 본문 동시 검색, 출처·페이지 표시 |
| 💬 챗봇 (RAG) | 근거 기반 답변 생성, 인용·연관 근거·그림, 멀티턴 토글 |

## ⚙️ 구성

| 역할 | 사용 |
|---|---|
| 이미지 임베딩 | `google/siglip2-base-patch16-224` (SigLIP2) |
| 텍스트 임베딩(다국어) | `BAAI/bge-m3` (교차언어, 1024차원) |

| UI / 실행환경 | Gradio · **CUDA / Apple MPS / CPU 자동 감지** |

## 🗂️ 청크 산출물 (색인 시 자동 생성)

색인하면 세트 폴더에 다음이 생성됩니다:

- `indexes/<세트>/chunks.jsonl` — 청크당 `id · text · url(파일#page) · section` (+ `char_len·ocr·flags`)
- `indexes/<세트>/verify_report.md` — **중복 가능 청크** 목록 + **사람이 원문 확인할 항목**(플래그별)

> 청크 규칙·필드 상세는 [`PRD.md`](PRD.md) §4.1 참조.

## 💬 챗봇(생성 답변) 실행 · 문제 해결

챗봇 탭은 로컬 **Ollama**로 답을 생성합니다. (🔍 검색 탭은 Ollama 없이도 동작)

**1) 준비 — Ollama + 모델**
```bash
ollama pull qwen3.5:2b
```
[Ollama](https://ollama.com)를 설치·실행해 두면 앱이 `http://localhost:11434` 로 호출합니다. (주소 변경은 환경변수 `OLLAMA_HOST`)

**2) 사용 순서**
1. **📁 색인 생성** 탭에서 매뉴얼 PDF를 먼저 색인
2. **💬 챗봇** 탭에서 색인 세트를 고르고 질문
3. 근거가 있으면 답변 + `[출처 파일 · p쪽]` 인용, 없으면 지어내지 않고 "매뉴얼 근거에서 확인되지 않습니다"

**3) Ollama `think` 설정 (중요)**
`qwen3.5` 같은 **추론(thinking) 모델**은 답을 사고 과정(`thinking`)에만 쏟고 최종 `content`를 비우는 경우가 있습니다. 그러면 챗봇이 빈 답을 받아 계속 "확인되지 않습니다"만 냅니다.
- 그래서 앱은 Ollama 호출에 **`think: false`** 를 넣어 사고 과정을 끄고 **답을 바로 생성**합니다 (`app.py`의 `ollama_chat_stream`).
- 다른 추론 모델로 바꿨을 때 답이 계속 비어 나오면 이 `think: false` 설정을 먼저 확인하세요.

**4) 자주 겪는 문제**
| 증상 | 원인 · 해결 |
|---|---|
| `Ollama 서버 연결 실패` | Ollama 미실행 → Ollama 실행 후 재시도 |
| `모델 … 찾을 수 없습니다` (404) | 모델 미설치 → `ollama pull qwen3.5:2b` |
| 답이 계속 "확인되지 않습니다" | ① 챗봇 탭에서 **색인 세트 선택** 확인 ② 코드/설정 변경 후 **앱 완전 재시작**(옛 프로세스가 7860 포트를 잡고 있으면 종료 후 재실행) ③ 고급 설정의 **텍스트 임계값**을 낮춰 근거 확보 |
| 첫 답까지 잠깐 멈춤 | 정상 — 모델이 답을 준비하는 시간(스트리밍으로 이어서 출력됨) |

**5) 로컬 / 외부 API 전환**
기본은 완전 로컬입니다. 챗봇 **'고급 · 생성 백엔드'**에서 OpenAI 호환 API로 **수동 전환**할 수 있으나, 그 경우 검색된 매뉴얼 내용이 외부로 전송됩니다(⚠️ 보안 자료 금지).

## 🔒 보안

- 기본은 **완전 로컬**입니다. 실제 선박 매뉴얼은 **로컬/사내망**에서만 사용하세요.
- 챗봇 **'고급' 설정에서 API로 수동 전환**할 때만 외부 호출이 일어나며, 이 경우 **검색된 매뉴얼 내용이 외부 서버로 전송**됩니다(전환 시 경고 표시). 보안 자료에는 사용하지 마세요.
- 원본·색인 데이터(`indexes/`, `*.pdf`, `crops/`, `pages/`)는 `.gitignore`로 저장소에서 제외됩니다.

## 🧠 설계 결정 요약

> "무엇을 만들었나"가 아니라 **"왜 이렇게 정했나"** 의 요약. 상세 명세는 [`design-packet.md`](design-packet.md).

**도구를 4개만 둔 이유.** 챗봇 에이전트에는 세트 목록 조회·근거 검색·이미지 열람·검증 플래그 조회 **네 도구만** 뒀다. 도구 수를 늘리기보다 각 도구의 **반환물이 서로 겹치지 않는** 편이 중복 호출·오작동을 줄이기 때문이다 — 이름(목록) / 참조(검색) / 이미지 실체(열람) / 플래그(검증)로 책임이 배타적이다. 검색은 이미지 *참조* 만, 열람은 *실체* 만 돌려주도록 경계를 그어, 모델이 임의 파일을 탐색하거나 검색 단계에서 답을 지어내는 경로를 막았다.

**권한을 나눈 기준.** 권한은 **부작용의 범위**로 갈랐다 — 로컬 읽기(세트·근거·이미지·플래그)는 되돌릴 결과가 없어 자동 허용, 코퍼스를 바꾸는 **색인 덮어쓰기**와 매뉴얼을 밖으로 내보내는 **API 전환·키 입력**은 사람 승인 대상이다. 특히 API 경로는 켜는 순간 검색된 매뉴얼이 외부로 전송되므로 **기본 비활성·행위 단위 승인·전송 경고**를 필수로 뒀다. 즉 기본값은 완전 로컬이고, 외부 전송과 데이터 변경만 사람의 명시적 결정을 요구한다.

**실패 뒤 행동의 근거.** 실패의 기본값은 **"지어내지 않기"** 다 — 근거가 없거나(`NO_EVIDENCE`) 생성이 끊기면(`LLM_CONN_FAILED`) 답을 만들지 않고 보류하거나 원인·다음 행동을 안내한다. 폐쇄형 RAG의 신뢰는 *틀린 답보다 "모른다"가 낫다* 는 전제에서 오기 때문이다. 저신뢰 근거는 숨기지 않고 '저신뢰'로 표시해 판단을 사람에게 넘기고, 안전 직결 절차는 **면허 기관사·원문 확인으로 이관**해 챗봇이 최종 판단 주체가 되지 않게 했다.

## 🧪 실험 — 루브릭 한 바퀴

- **실험 이름**: `think` 파라미터 A/B (베이스라인 ↔ 채택)
- **실험 대상**: 현재 구현(Gradio + Ollama `qwen3.5:2b`), 세트 `O2_ANALYZER`(영문 SMIT7000 산소분석기 매뉴얼)
- **루브릭(목표값)**: 자료 안 질문 → `cited`=예·`grounded`=예 / 자료 밖 질문 → `refusal`=예
- **고정 조건**: 텍스트 임계값 0.4, 단발형, 질문·순서 고정
- **바꾼 변수(단 하나)**: Ollama `think` (true=추론모델 기본 ↔ false=채택)

**고정 질문 세트**
- 직접: Q1 "산소 분석기 센서 교체 주기는?" · Q2 "산소 분석기 교정 방법은?"
- 다청크: Q3 "센서 수명과 보관 온도 조건을 함께 알려줘" · Q4 "산소 분석기 설치와 경보 설정을 함께 알려줘"
- 자료 밖: Q5 "오늘 부산 날씨 알려줘" · Q6 "김치찌개 레시피 알려줘"

**Run B — `think:false` (채택)** · 목표값 ↔ 실제 판정값
| Q | 유형 | 검색 hit | cited | refusal | grounded | 목표 | 판정 |
|---|---|---|---|---|---|---|---|
| Q1 | 직접 | 5 | ✅ | – | ✅ | cited+grounded | ✅ 통과 |
| Q2 | 직접 | 5 | ✅ | – | ✅ | cited+grounded | ✅ 통과 |
| Q3 | 다청크 | 5 | ✅ | – | ✅ | cited+grounded | ✅ 통과 |
| Q4 | 다청크 | 5 | ❌ | – | ❌ | cited+grounded | ❌ **실패(인용 누락)** |
| Q5 | 자료밖 | 5 | – | ✅ | – | refusal | ✅ 통과 |
| Q6 | 자료밖 | 4 | – | ✅ | – | refusal | ✅ 통과 |

**Run A — `think:true` (베이스라인, 되돌림)** · 인스코프 2문항
| Q | content 길이 | thinking 길이 | 앱 표시 | 판정 |
|---|---|---|---|---|
| Q1 | 0자 | 13,092자 | "확인되지 않습니다" | ❌ 오탐 refusal |
| Q2 | 0자 | 11,442자 | "확인되지 않습니다" | ❌ 오탐 refusal |

**관찰**
- `think:true`는 답을 전부 `thinking`에 쏟고 `content`가 비어, 자료 안 질문인데도 앱이 "확인되지 않습니다"로 **오탐 거부**(cited·grounded 0).
- `think:false`로 바꾸자 자료 안 질문 3/4가 인용·근거를 갖춘 답을 냄.
- 자료 밖 Q5·Q6은 검색이 hit 5·4로 잡혔는데도(임계값 0.4가 낮아 잡힘) LLM이 폐쇄형 지시대로 거부 → **거부는 검색 게이트가 아니라 근거 프롬프트가 담당**함을 확인.
- **실패(보존)**: Q4(설치+경보, 다청크)는 답은 했으나 `[출처]` 인용을 빠뜨림 → 다청크·장문에서 인용 누락 경향. 소형 2b 모델은 답에 한/영/중 혼용도 관찰됨(품질 한계).

**결정**
- ✅ 채택: `think:false` (되돌림: `think:true`) — `app.py`의 `ollama_chat_stream`에 반영됨.
- 다음 수정이 **보존할 것**: 자료 밖 거부(Q5·Q6), 직접 질문 인용(Q1·Q2).
- 다음 수정 **후보**: 다청크 인용 누락(Q4) — 문장별 인용 지시 강화 또는 리랭킹.

## 🚧 실행하지 않은 것과 이유

**구현을 미룬 부분**

| 미룬 것 | 이유 |
|---|---|
| 그림 직접 판독(비전 입력) | v1은 **텍스트 근거 합성만**. 텍스트 grounding을 먼저 안정화 (`qwen3.5:2b`가 멀티모달이나 도면 직독은 향후) |
| 색인 재설계·도메인 파인튜닝·정비 기록 통합 | **범위 밖** — 현행 색인을 계약으로 사용 (PRD §2.2) |
| `section` 자동 검출(헤딩) | 북마크 있으면 채우고 없으면 `[검증 필요]`. 레이아웃 기반 자동 검출은 향후 |
| 문단–그림 정밀 연결 | 현재는 **같은 페이지** 단위로만 연결 |
| 멀티턴 세부 정책 | 토글만 제공, 맥락 유지 범위·초기화 방식 미확정 |
